`blume init` now installs dependencies after scaffolding, using the package manager that ran it (`bunx blume init` → `bun install`, `npx blume init` → `npm install`, and so on) or the one given with `--package-manager`, so the generated project runs `dev` straight away. Pass `--no-install` to only write the files. When the install fails, the scaffold is kept, the exact command to retry is printed, and the command exits non-zero. `--eject` now ejects in the same run instead of asking you to install first. With pnpm, `init` also writes a `pnpm-workspace.yaml` that approves esbuild's build script and declines `@scarf/scarf`'s telemetry postinstall, so pnpm 10 and later don't fail the install over unapproved builds; it skips this when a `package.json` already exists or the folder is inside a pnpm workspace. With Yarn 2 or later, `init` writes a `.yarnrc.yml` that sets `nodeLinker: node-modules`, since Yarn's default Plug'n'Play install leaves Blume's generated Astro project without the `node_modules` it resolves packages from. In an existing pnpm workspace or Yarn project, `init` leaves that workspace's config alone and says what it still needs (esbuild's build approval, or the `node_modules` linker).
